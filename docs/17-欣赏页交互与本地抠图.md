# 欣赏页交互与本地抠图

## 使用方式

1. 进入欣赏作品，默认显示完整画作。鼠标靠近人物时才显示姓名和轮廓，键盘也可逐个选中人物。
2. 点击人物或其卡片，画作平滑放大平移，将人物上半身置于中央。背景暗化，透明人物层保持原画色彩并高亮边缘。标签保持屏幕大小并避开画布边缘。
3. 点击人物之外的背景、点击返回全景或按Esc还原。已选聊天对象与对话保留。
4. 下方同一角色ID只显示一个入口。多个实例保留独立聚焦位置，共用角色档案、知识与聊天；不同ID的同名人物不会被合并。
5. 头像采用已确认的手动面部框，其次采用确认画面中的面部框，无面部框则取人物上方约三分之一。草稿头像不会进入体验。

已确认身份和人物资料但没有有效知识的人物可以观看；发送框禁用并说明资料待完善。没有确认身份的实例不会被自动命名或开放聊天。

## 本地分割

现有依赖`torch`、`transformers`和`Pillow`即可运行，无额外收费API。首次部署在项目目录明确准备模型：

```sh
.venv/bin/python scripts/prepare_cutouts.py
```

脚本下载约39MB的[官方SlimSAM权重](https://huggingface.co/nielsr/slimsam-77-uniform)，固定提交`72a5ae6ca4d1da579a001f6f008b6fb949282c10`，仅下载safetensors及配置，不执行远端代码。页面不会自动联网下载模型。已在本机完成准备。

进入体验后，后台按会话的确认画面和人物框在CPU进行分割。每个实例使用局部画面、人物框和头部提示；相邻实例的头部作为排除提示。清理碎点与衣物内部孔洞，输出透明PNG。单一锁与文件二次检查避免并行重复计算，缓存采用临时文件原子替换。

缓存位于`data/experience-cutouts/`，键包含原画字节SHA-256、人物框、头部提示和分割策略版本；不包含聊天内容或密钥。它是可重建的派生缓存，不建立制作资料或改写项目版本。旧体验继续用自己的画面、头像和框，普通发布修改不会改变旧会话的缓存身份。

密集遮挡、低清画作或不准确的人物框可能带入邻人或部分背景；当前自动抠图不是人工精修。模型缺失、文件缺失和单个分割失败均明确显示，不伪造成功轮廓，也不阻止其他人物交谈。

## 接口

|接口|作用|
|---|---|
|体验详情中的`figures`|已确认的画中实例、角色ID、人物框、头像框及`canChat`|
|体验详情中的`people`|满足身份、档案与有效知识条件的可交谈实例，保持原有约束|
|`POST /api/projects/{pid}/experience/sessions/{sid}/cutouts`|本地生成／读取该会话的派生轮廓，按实例返回URL或错误|
|`GET /api/projects/{pid}/experience/sessions/{sid}/cutouts/{key}.png`|只提供该项目及该会话允许的轮廓，禁止任意路径或其他缓存键|

这些接口不发送对话请求、不提交视频、不修改制作项目版本。

## 对话显示

观众问题在右侧，角色回答在左侧；显示头像、称谓、发送时间，保留换行与长文本自动折行。线索卡片与原文依据分开显示，明确记录后才解锁。消息区独立滚动，正在阅读旧消息时不因普通轮询强制滚动。发送失败保留输入；切换角色保留各自未发送的问题，群体实例共用同一份输入和记录。

## 验证与启用

自动化验证覆盖确认头像优先级、草稿隔离、上方三分之一回退、群体卡片、聚焦上半身、掩膜透明度、缓存去重、项目不变、会话隔离、旧会话框不变、失败隔离和轮廓清理。浏览器使用临时项目、真实古画的只读复制以及聊天／视频替身；不把模拟回答当作模型质量验收。

首次隔离验收时正式服务未重启。后续收到正式网页故障反馈并获准后，已重启服务，正式批量清单及人物轮廓加载均通过。没有运行全项目迁移脚本，原有项目按读取兼容规则恢复依据；正式批量确认保存了本项目的版本提醒元数据。源码、数据备份和恢复步骤见[版本提醒与一键确认](16-版本提醒与一键确认.md)。本页不需要数据库新增表，派生轮廓可重新生成。最终数字与截图见项目根目录`VERIFICATION.md`。

后续修复还包括：群体实例使用各自框内头部进行分割，不误用共享头像的绝对坐标；不显示虚线假轮廓；抠图失败可展开原因并重试本地处理。聊天输入框明确显示可输入区域。大型旧项目使用隔离的历史读取缓存，轮询不重叠，后台暂停，减少页面长时间等待。
