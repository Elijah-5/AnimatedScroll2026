# 统一作品资料库

2026-11-01 起，作品档案、历史资料、人物画像与研究依据统一进入资料实体。本文替代第13、14章中两个独立资料面板及独立历史审核、采用流程；原八张 SQL 表和旧审计记录继续保留。

## 使用流程

1. 导入画作、文献或填写资料输入，明确点击「整理资料」或「整理文献」。同一任务完成原整理和结构化归纳，不再分别整理两个资料库。
2. 已有项目点击「根据现有资料补充整理（调用 LLM）」。先本地映射现有资料、人物、原页条目和旧库，再分组归纳已定位的原文，不重新上传完整 PDF。
3. 查看作品档案、历史背景、人物与关系、来源与原文、研究判断、待补充与冲突六个视图。资料人物包含研究者、作者、收藏者及背景人；只有显式关联的 characterId 属于创作人物。群体实例编号各自保留。
4. 保存为同一份资料草稿，使用资料确认、撤回或「一键确认本页／全项目一键确认」。不再有独立历史发布和「采用历史八表」步骤。

文献资料提供两种输入模式：「上传文献文件」和「输入文本」。文本可填标题、出处和完整原文，不必先分成三段；两种模式共享文献列表、勾选范围、「整理资料」按钮和同一个 documentAnalysis 结果格式，并生成同一结构化草稿。原三段输入作为已采用摘要折叠保留，可复制到文本模式。文本编辑器草稿保存在 material.draft.literatureInput；未保存为文献的编辑缓冲不会作为模型依据或导出内容。

「人物与关系」已恢复关系图，同时呈现统一资料关系和既有关系列表中的线索，保留每个来源及其确认状态，不自动把草稿当成确认关系。群体共享节点；点击角色进入现有档案，点击方向连线查看原文及来源。可明确开启「显示其他资料人物」，画外、画中未关联及范围未定仍分别标记，不强行判定身份。

打开、保存、确认、批量确认及迁移均不调用模型。空缺保持为空并附原因；无依据的年代、作者归属和事件不能凭常识补全。人工确认不表示独立核实了史书版本。

## 唯一权威内容

权威位置为 `workspace.entities['material:main'].draft.structured`，确认后复制到同实体的 `published.structured`。顶层 structured 仅为旧工作区镜像。项目仍存于 projects.body；历史确认及依赖存于 revisionArchive，不改写既有确认快照。统一数据 schemaVersion 为1.0。

| 集合／字段 | 内容 | 主要字段 |
|---|---|---|
| artwork | 作品档案 | name、artist、period、storyPeriod、medium、dimensions、collection、accession、description、circulation、storyOneLiner |
| people | 资料人物及角色关联 | id、name、characterId、roleType、scope、contextRoles、annotationIds、referenceIds |
| events | 历史背景 | id、title、text、phase、time、category、referenceIds |
| relations | 方向关系 | id、fromId、toId、label、category、referenceIds |
| statements | 逐句人物画像 | id、personId、aspect、text、category、referenceIds；profileField 表示沿用人物档案字段 |
| research | 原整理条目及研究判断 | id、text、topic、author、publication、category、referenceIds |
| sources | 各版来源文本快照 | id、version、title、text、citation、sourceType；可附 documentId、documentFilename、page、genre、resource_uri |
| evidence | 精确引文及核对身份 | id、sourceId、sourceVersion、quote、start、end、edition、locator、level、verification |
| missing | 缺失及无法恢复的依据 | field、label、reason |
| conflicts | 保留值和待核对候选 | id、field、current、candidate、referenceIds、reason；明确选择后记录 resolution |
| legacyVersions／legacyTables | 迁移审查用旧表及审核版本 | 保留原 ID、行版本与审核文本，不进入下游模型输入或叙事包 |

artwork 每个字段为 `{value, referenceIds, origin, generatedValue}`。条目同样记录 origin，生成条目另记 generatedValue。人工修改优先；整理更新空字段或未改动的生成字段，矛盾值进入 conflicts。修改事实文字、方向或时间会解除旧引用并保留 previousReferenceIds，避免修改后的文字冒充旧引文所支持的结论。

circulation 写画作本身的制作、收藏和流传；events 写画中故事的历史。无法确定时段为「未明」，无依据的时间留空。人物档案继续编辑同一创作角色；已改动的档案字段不会被旧 profileField 画像作为当前事实再次提供给欣赏 Agent。

## 来源规则

| 字段 | 允许值与规则 |
|---|---|
| evidence.level | direct 原书文本、indirect 研究资料转引、research 研究资料、observation 画面观察、creator 创作者输入 |
| verification | unverified／edition_verified；模型不能提升核对状态 |
| category | supported 资料记载、inference 解释推断、uncertain 待核对、fiction 创作设定；资料记载不等于独立核实史实 |
| sourceVersion | 绑定的来源版本，旧引文继续按旧文本校验 |
| start／end | Unicode 码点位置，必须满足 source.text[start:end] == quote；不改字、标点或截断改写 |
| edition_verified | 必须为 direct、有具体 edition、来源明确为 historical_primary，且由人工对照版本核对 |

保留文献条目的 topic、assertion、indirectSource 和目标画作信息。论文转引不会变成原书核对，书目未注明则标记待核对。PDF／OCR 引文保留文档及页码，可展开来源文本。补充来源表单支持原书版本、体裁、回查地址、卷页和逐字引文。

## 管线消费

确认读取为 structured.view(p)，兼容来源读取为 structured.material_sources(material)，实体通过 consumption.confirmed 读取。

| 环节 | 读取范围 |
|---|---|
| 资料／文献整理 | 当前输入、claims／people、已定位原页、手工来源与旧库，生成同一草稿 |
| 人物视觉匹配 | 确认统一资料及已有创作人物，不自动添加作者或研究者 |
| 剧情、文化与关系线索、分镜 | 确认档案、事实、原文及旧依据版本，保留人工摘要和创作意图 |
| 人物知识 | 沿用有效线索分配及人工采用、确认规则 |
| 视频提示词编译 | 当前镜头及相关角色事实；审核仍取决于实际文本、图片内容及顺序、模型和参数 |
| 欣赏 Agent | 仅该角色确认档案、自己的画像、获准线索和依据；不传整库、其他人物知识或完整剧情 |
| 叙事导出 | schemaVersion 3.2，包含统一确认资料、依据版本、缺失、争议与版本提醒；排除密钥、聊天、旧未确认归档 |

保存草稿不影响下游，发布后为非阻塞提醒，不取消确认。旧会话继续使用原快照。资料版本变化不撤销实际请求未变的视频审核。离线包不提供实时模型服务；既有3.1文件及资产不会被迁移改写，本轮没有新增离线包导入器。

## API 与投影

| 接口 | 行为 |
|---|---|
| GET /api/projects/{id}/structured | 当前统一草稿或只读兼容预览、字段名及确认版本，不写入 |
| PUT /api/projects/{id}/studio/drafts | kind=material、id=main，data.structured 随其他资料校验保存 |
| POST /api/projects/{id}/studio/jobs | task=structure_materials，沿用缓存、取消、版本与人工编辑保护 |
| POST /api/projects/{id}/documents/text | 保存文本为文献，不调用模型；携带项目版本、可选 documentId/sourceVersion，重复内容复用，编辑保留来源 ID 和旧版本 |
| studio/confirm、revert、batch-confirm/preview、batch-confirm | 同一资料确认、撤回与原子批量流程 |
| 旧 history GET | 保留读取及旧审核信息 |
| 旧 history 写接口 | HTTP410，提示刷新并使用作品资料库，禁止另一套草稿写入 |

运行期间输入或结果区变化，结果存为旧输入建议，不覆盖人工编辑、不自动重试。缓存按配置和依据摘要分组；无效结果不进入成功缓存。

文本编辑保留各版文件，来源的 documentFilename 指向对应文件；导出按当前确认资料及历史引用收集原版文件，不以文献ID直接替换为最新未发布文本。

原八表随确认事务更新严格投影：works 来自 artwork，background_episodes 来自时段明确的 events，persons/work_persons 只接范围明确的具名人物，hist_sources/quotations 只接有版本、体裁、回查位置且人工逐字核对的直接引文；保留旧合规 inferences/person_lines。转引、群体及不确定内容留在统一结构，不强压进旧表。artwork_sources 每个来源只索引最新版本，统一快照保存全部版本。

## 迁移、上线及恢复

实施前源码与完整数据备份：上级 merge-backups/unified-library-20261101T160734Z，227个文件及 SHA-256 已核对。备份包含私有配置，勿分享。上线前另备份当时最新数据，保留制作期间新增内容。

本次上线前恢复点为 merge-backups/unified-rollout-20261101T164150Z（237个文件、SHA-256 验证通过）。正式三个项目仅暂存统一草稿，各增加一个项目版本，旧确认内容、历史八表、体验及任务逐行核对不变；详见 unified-rollout-check.json。用户仍需按正常入口发布草稿。

在仓库目录预览，不改数据、不调用模型：

```sh
.venv/bin/python scripts/migrate_unified_library.py
.venv/bin/python scripts/migrate_unified_library.py --project-id 85e0f870d8bc
```

暂存到同一资料草稿，不发布、不改旧确认，重复执行跳过已迁移项目：

```sh
.venv/bin/python scripts/migrate_unified_library.py --apply
```

已确认旧 SQL 和待确认旧草稿均保留 ID 与审核记录，不同值进入冲突，无法恢复的逐字依据明确列因。首次确认前沿用原确认内容。任务完成后切换正式服务：

```sh
.venv/bin/python scripts/server_control.py status
.venv/bin/python scripts/server_control.py restart --no-browser
```

恢复时先关闭服务并另存当前完整项目及 data，核对备份清单，在新目录恢复源码和完整 data 后验证。不要覆盖运行中的 SQLite。只撤回统一草稿可使用资料现有撤回入口，不删除旧确认、聊天或视频。

本轮使用模型替身，不能代表真实模型史学归纳质量；MySQL 未实际连接，未执行 SQLite→MySQL 迁移。测试与副本验收详见 VERIFICATION.md。
