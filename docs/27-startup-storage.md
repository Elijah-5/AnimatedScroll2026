# 首次加载与历史存储优化

后续已按用户要求清理重复备份，仅保留最新完整恢复点；当前路径以 `.runtime/backup-retention.json` 为准。日常手动副本与体验记录范围见[第28章](28-manual-copies-and-reader-records.md)。下面旧备份路径仅记录当时实施过程。

本轮不删除制作内容、历史操作、聊天、线索进度或体验快照，不调用模型，不重建已有体验。

## 检查结果

优化前 SQLite 为 5,174,599,680 字节（约 4.82 GiB）。主要空间来自 234 条操作记录中重复保存的完整 `before` / `after` 项目快照；并非聊天记录过多。当前《步辇图(2)》项目约 53 MiB，其中约 33 MiB 是可以重新计算的依据提醒。

此前页面初始化分别读取项目列表、编辑内容和检查结果，多次解析完整项目；空闲轮询也解析完整 JSON 以读取版本。历史表虽然没有整表发送到浏览器，项目内部的历史和派生提醒仍造成重复解析。

## 读取路径

- 页面启动改为 `GET /api/studio/bootstrap?projectId=…`，一次返回项目列表、轻量编辑内容及制作检查。
- `studio_read_models` 保存与项目同时提交的编辑投影和检查缓存。项目写入会清除旧投影，正常保存会在同一事务内建立新投影；直接 SQL 修复也会触发失效。
- 检查缓存还校验图片、视频文件及视频任务变化。规则代码变化会使旧缓存失效。
- 空闲轮询只读取项目标识与版本，不反复解析整个项目。运行任务状态独立合并；首次缓存缺失时才从完整项目恢复。
- 启动不读取审计历史，不改变体验会话和资源清单；已有体验继续按其固定快照恢复。

## 无损压缩

`content_snapshots` 以原文 SHA-256 为键，保存 zlib 压缩的完整快照。事件的 `before` / `after` 存引用；相同原文复用同一个快照。数据库读取适配层只对这两个历史列解码，旧历史接口仍取得原始 JSON；新旧存储格式可混用。

当前项目仅移除实体顶层的派生 `basisWarnings`，展示时按需重算。人物资料、来源、确认、生成依据、历史版本及审核记录保持；优化前当前项目的精确原文另外保存为不可变快照。

压缩工具只输出到新的副本，拒绝覆盖源库。每个历史快照解压后逐字节校验，再复核全部历史记录的逻辑哈希；聊天、体验、任务及其他持久表逐表校验。最后执行 SQLite 完整性检查。

## 验证

- 原始数据副本：5,174,599,680 → 885,997,568 字节，约减少 83%。234 条历史完整保留，共 227 个去重快照。
- 副本预热后的启动接口约 0.13–0.20 秒，响应约 2.7 MB；这是本机接口测量，不代表所有设备的完整渲染时间。
- 浏览器完成三次初次／刷新加载：每次仅一个 bootstrap 请求，无额外项目列表、编辑接口或历史请求。副本编辑自动保存后刷新仍保留，控制台无错误。
- 372 项后端、57 项前端状态测试及构建通过。新增缓存失效、事务一致性、轮询不读大快照、压缩去重、损坏引用拒绝、全表保留及兼容还原测试。
- MySQL 的表结构和迁移工具已兼容两个新表；本轮未执行迁移，也未做 MySQL 实际连通验收。

正式上线复核：最新数据库 5,180,542,976 → 888,688,640 字节（包含预热缓存），整个 `data/` 从约 5.6G 降到 1.6G。234 条事件、4 个体验会话和 17 条体验对话任务记录均保留，包含实施期间新增的聊天。正式启动接口三次读取分别为 0.206、0.161、0.160 秒，均返回 200，未调用模型。正式浏览器打开及刷新正常，人物档案恢复、控制台无错误；前端原进程保持不变。

实施前完整源码与数据备份：`../merge-backups/startup-storage-20261101T234928Z/`，附文件清单和 SHA-256。

正式切换由 `scripts/rollout_storage.py` 完成：等待生成、对话和资源准备结束，正常停止后端，补备份最新完整数据，再压缩此最新副本。全部校验成功才替换数据库并预热读取缓存；保留前端进程。最新备份及校验报告的绝对路径记录在 `.runtime/storage-rollout.json`。

本次正式数据备份为 `../merge-backups/storage-rollout-20261102T001031Z/`；全表及历史还原校验为 `.runtime/storage-20261102T001031Z/verification.json`。

仅需重启时继续使用 `scripts/server_control.py restart`。当前代码可读优化前的数据库，历史压缩不是删除操作。

若必须退回不认识压缩引用的旧代码，应先停止服务，备份**当时最新**的完整 `data/`，从最新数据库生成兼容副本：

```sh
.venv/bin/python scripts/compact_storage.py --inflate \
  --source data/projects.sqlite \
  --output .runtime/rollback-latest.sqlite
```

工具保留最新制作、聊天和体验表，仅将历史引用展开为原始 JSON。检查输出成功后，再在停服状态切换兼容副本与代码。输出路径必须不存在，需为展开后的较大数据库预留空间。不要用实施前旧备份覆盖运行期间新增的聊天或制作。

后续再次压缩也必须在服务停止或完整一致备份上操作，并指定新的输出路径；不要直接修改在用数据库。
