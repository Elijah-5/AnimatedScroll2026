# 简化审核、生成与工作流

当前操作顺序：**资料与基础人物 → 剧本大纲 → 线索库 → 人物档案与对话设定 → 分镜管理 → 欣赏作品**。

## 操作

每页顶部显示当前步骤、可用内容数量、必要缺项和下一步。AI 生成只处理当前步骤；已经可用的基础人物可直接供剧情和线索使用。人物知识与人设在线索之后集中准备。欣赏页面只开始或恢复会话，不生成制作前置。

输入停止约 800 毫秒、失焦或开始生成时自动保存，输入法组词期间不提交。保存不调用模型。浏览器 IndexedDB 按项目保留待保存输入；网络失败仍保留输入，请恢复连接后继续。并发修改不同字段自动合并，修改同一字段时展示选择。切换制作页不等待全项目保存或重新检查。

已移除新版界面的“一键”、保存并应用、撤回修改、更多操作、发布改动、制作版本号和版本差异面板。底层历史与旧接口仍保留，便于兼容和恢复。

## 四种状态

| 状态 | 图标 | 含义与操作 |
| --- | --- | --- |
| incomplete／待补全 | 灰色虚线圆 | 缺少当前功能必要内容，显示具体原因；旧来源无法证明时也明确说明，内容仍可按实际可用性消费。可选作者、年代等缺失不阻止整组使用。 |
| AI | 黄色星芒 | 实际包含未人工核对的生成内容，可直接继续制作。 |
| human／人工 | 绿色人物勾选 | 完全人工填写，或对整组内容作过明确人工确认。 |
| outdated／待更新 | 灰色时钟箭头 | 附加提醒：实际使用的相关依据改变；只在可恢复依赖记录时判断，可与 AI／human 共存。 |

每组只有一个主状态。人工编辑 human 内容后仍是 human；局部修改 AI 内容仍是 AI。新 AI 内容真正加入才撤销对应审核；相同生成结果和未采用建议不会撤销。确认会记录已核对内容校验值和相关依赖校验值，不改写原生成来源，也不把论文转引或推断升级为已验证史实。

## 审核单位

| 内容 | 稳定单位 ID | 统一范围 |
| --- | --- | --- |
| 画中人物卡片 | `visual:<annotationId>` | 身份对应、观察描述、画面设置，一处“确认此人物” |
| 群体画中人物叠卡 | `visual-group:<characterId>` | 同一群体全部身影共用资料与确认，位置框仍逐个选择；原逐人观察保留 |
| 文献资料集合 | `documents:main` | 原文、整理结果、候选 |
| 作品资料库 | `library:main` | 六个视图 |
| 大纲 | `outline:main` | 创作方向、剧情、共同生成的叙事线索及体验设置 |
| 线索库 | `clues:main` | 全部线索 |
| 人物档案 | `character:<characterId>` | 小传、知识、人设、引导问题，群体实例共用角色 |
| 分镜 | `storyboard:<storyboardId>` | 人物、区域、完整提示词及首尾描述 |
| 视频结果 | `video:<jobId>` | 单个视频结果，付费请求审核仍独立保留 |

共享内容按成员校验值复用审核记录。普通保存、项目／线索改名、无关资料修改和程序版本变化不构成 outdated。引用删除、素材缺失或格式错误仅影响直接涉及的新操作；旧聊天和视频历史继续保留。

## 接口与持久化

- `GET /api/projects/{pid}/studio/editor`：轻量编辑投影，历史依据、旧批量回执和历史内容留在服务端。
- `GET /api/projects/{pid}/studio/units`：页面汇总、审核单位、必要缺项、可执行下一步。
- `PATCH /api/projects/{pid}/studio/units/{unitId}`：字段级自动保存，携带项目版本、请求编号及每个字段的原值／新值；事务内比对当前值，支持不冲突字段合并。
- `POST .../studio/units/{unitId}/confirm`：内容及依赖校验值、请求编号；事务中统一记录成员审核，不调用模型。
- `POST .../studio/generation-batches`：`page`、`mode`（initial／regenerate）、`targets`、项目版本和请求编号。只在当前步骤组排队。
- `GET .../generation-batches/{id}` 和 `POST .../{id}/continue`、`cancel`：持久进度、取消、显式恢复；完成阶段不重复生成，输入变化的建议保留，不覆盖人工编辑。
- `GET .../studio/poll?compact=true`：变更时返回轻量投影；切页不发送模型请求。

项目 JSON 的 `workspace.reviewUnits` 保存成员来源、已核对校验值、单位相关依据和幂等回执，不新增 SQL 表。叙事包 3.4 增加分组审核及来源，不包含请求回执、密钥或观众聊天。旧确认和编排接口保留，但新版界面不使用全项目编排。

## 旧记录与恢复

`scripts/migrate_review_units.py` 默认只预览；`--apply` 才向项目 JSON 补充可证明的审核记录。仅继承明确人工确认事件；不因旧 `confirmed` 字段就推定人工审核，不改变史实等级，不执行数据库结构迁移。旧“确认人物”只证明当时点选的实例；整组人工确认按成员内容校验值继承。

实施前备份：`merge-backups/review-ui-20261101T200623Z`，含源码、完整 data 和 SHA256 清单。上线前另建最新完整备份，避免覆盖实施期间新增制作和聊天。恢复时先停止本项目服务，单独保留当前完整数据与聊天，再恢复所需源码；若仅回退界面可保留新增 reviewUnits 字段，旧程序兼容读取。数据恢复须针对选定项目／时点，不能直接用实施前整库覆盖最新数据。

本轮不调整 API Key 或模型，不追加真实请求或付费视频，不执行 MySQL 迁移；MySQL 未实际连通验收。模型替身与浏览器验收记录见 `23-review-verification.md`。
