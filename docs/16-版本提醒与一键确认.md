# 版本提醒与一键确认

本轮将普通上游修改从“连锁失效”改为可继续使用的版本提醒，并增加当前页、全项目批量确认。历史八表保留独立审核。

## 使用方式

- 保存草稿不影响已确认内容。发布上游修改后，下游继续保留确认状态，显示“基于旧版本”。展开可查看原依据版本、当前版本和字段差异。
- “已核对，继续使用”只记录复核，不改写原生成依据，不增加内容版本，不调用模型。再次发布新的上游内容后，会针对新版本重新提醒。
- 各制作页标题旁提供“一键确认本页”；检查抽屉提供“全项目一键确认”。预览清单后一次确认，符合条件的草稿与复核项统一保存，未匹配、冲突、未配置、生成中等项目列出跳过原因。
- 已选好角色的画面人物可一起确认；同一群体的多个实例分别列出，共用人物档案和知识。不会替未匹配人物选择身份。
- 不自动采用模型建议，不自动解决 AI 一致性建议，不调用模型或视频服务。历史八表仍通过独立的原文与差异审核入口确认。

## 数据与版本

`workspace.revisionArchive` 保存按条目和版本索引的已确认内容及依赖。原有 `refs` 保留确认依据，生成候选使用 `draftRefs`；确认时另保留 `generationRefs`。`reviewedRefs` 记录已复核到哪个上游版本，和内容版本分开。

读取旧线索时，按历史依赖版本取原文，并核验引用；不能拿新版原文误判旧引用。改线索标题等内容时，可以保留仍能逐字核对的旧引用，不会把旧版引用悄悄改成新版。

同次生成的剧情及其子线索在首次确认前为 r0 草稿。首次确认后绑定正式父版本，生成时的 r0 信息另行保留，不把草稿冒充成历史确认版本。

旧项目先从审计记录恢复版本。能恢复的失效／复核条目改为继续可用；无法恢复的明确提示原因，不伪造历史依据。此类缺失、删除对象、无效引用与缺失素材仍会阻止直接涉及它们的新操作。

## 批量确认接口

| 接口 | 行为 |
|---|---|
| POST `/api/projects/{pid}/studio/batch-confirm/preview` | 接收 `version`、`scope=page/project`、`page`、可选条目 `keys`；返回可确认项、跳过原因、项目编号和 `previewHash`。 |
| POST `/api/projects/{pid}/studio/batch-confirm` | 携带同一范围、`version`、`previewHash`、`requestId`，重算清单后提交。 |
| POST `/api/projects/{pid}/studio/acknowledge` | 接收 `version`、`kind`、`id`；仅复核已确认内容的旧依据，不发布该条目的草稿。 |
| POST `/api/projects/{pid}/studio/suggestions/{id}/adopt` | 明确采用基于旧输入的生成建议，仅合入没有人工冲突的字段。 |

预览绑定具体项目，不能跨项目复用。提交按人物对应、资料、人物、创作设置、剧情、线索、知识、分镜的顺序处理；全部可确认项一个事务保存，项目版本只增加一次。预期校验失败的条目跳过，存储异常全部回滚。相同请求编号重复提交返回原批次结果；并发版本变化返回409，不覆盖编辑。

模型运行期间输入或结果区域被修改时，结果保存到 `workspace.generationSuggestions`，标明原输入版本，不覆盖人工内容、不自动重试。可展开查看后明确采用未冲突部分。

## 视频与体验

- 视频审核及去重使用实际提交文本、参考图片内容与顺序、模型和参数；人物简介、知识等元数据变化本身不撤销相同请求的审核。
- 旧视频保留播放、下载和选择入口，显示制作版本。新的结果不会自动替换已经选择的视频。
- 新任务存储实际请求哈希。旧任务若留有输入图片，可按真实请求体核对重复请求；提交状态不明且依据不全时拒绝重新提交。已知失败仍需明确重试，重启不会重新计费提交。
- 体验会话保存创建时的已确认内容和知识快照。上游普通修改后显示“正在体验旧版本”，聊天与线索进度继续保留；重新开始才进入最新版。
- 对话只读取该会话中该人物的已确认档案、知识绑定和相应版本原文。未把整个项目或其他人物知识作为新增对话上下文。
- 同版本任务完成后可加入会话，不能自动混入另一版分镜。观众记录的线索保存当时的内容与依据版本。
- 叙事包格式升级为3.1，包含 `basisWarnings`、`basisVersions` 及视频来源版本，不包含观众会话、聊天或密钥。普通版本提醒不会阻止导出，缺失或不合法内容仍须处理。

## 迁移与恢复

实施前已备份当前源码及完整data：`../merge-backups/version-notices-20261101-012302/creation-agent-demo`。清单与SHA-256在同级`manifest.json`，共189个文件，已逐项核对。依赖、模型缓存、构建输出及运行日志未纳入源码备份；备份目录权限700，包含本机.env，勿分享。

迁移工具默认只预览，显式`--apply`才保存项目元数据：

```sh
.venv/bin/python scripts/migrate_revision_notices.py
.venv/bin/python scripts/migrate_revision_notices.py --apply
```

已先在数据库副本验证：三个项目的已确认文字保持一致，重复迁移不再写入。原《折槛图》的创作设置及三个剧情曾引用未确认的 `material:main r0`，审计中没有对应确认版本。这四项会明确列出历史依据缺失，不自动确认，不伪造原文或版本。

需要恢复时先关闭服务，保留现目录，再从上述备份恢复为原目录名；可复用保留目录中的`.venv`、`node_modules`和模型缓存。不要在服务运行时替换数据库。迁移不切换SQLite/MySQL，不推送GitHub。
