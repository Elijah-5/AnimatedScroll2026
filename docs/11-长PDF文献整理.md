# 长PDF文献整理

## 操作流程

1. 在古画资料库导入画作，再到「文献资料」导入PDF／TXT／Markdown。PDF限100MB、300页，文件分块落盘，后台本地解析；不调用LLM或自动OCR。
2. 展开原文预览，比较原页和提取文字。默认PDFium，异常时备用pypdf；图片页、空白页和文字映射异常分别提示。需要时显式点击「OCR本页 · 调用 LLM」，结果仍待校对。
3. 勾选文献，填写目标画作名称，页码默认全文，可输入`1-3,5`。点击「整理选中文献 · 调用 LLM」；目标画名用于限制分析对象；采用结果时同步项目的画作名称，同名项目自动加序号。
4. 系统按段落分批提取，复核内容用途，再分别生成三段摘要、人物提及和原文引用。查看结果，选择采用哪些摘要及本画人物；同名已有角色只有勾选更新才会修改，保留原ID。
5. 采用不触发人物检测或视觉匹配。另行点击相应按钮，并逐人核对确认。人物确认和下游发布仍遵循现有版本规则。

人物候选卡片右上角的“编辑”可修改姓名、身份、简介、经历和关系。保存只更新候选，取消不改动原内容；再选择采用后更新人物档案。原文、引用、候选编号及已有角色ID保留，手动改名不会重复建档，也不调用模型。保存失败时保留输入供重试。

## 引用与人物范围

- 保留完整页文。每个引用记录文献ID、PDF页码、来源ID及版本、字符起止位置和逐字原文；展示引用可直接定位原页。PDF换行造成的空白差异会绑定回原始完整片段，不做近义改写或模糊补引。
- 摘要仅是整理结果，不作为一级史料；后续生成引用所采用内容对应的PDF原页片段，不把所有文献全文拼入上下文。
- 人物提及区分本画、历史背景、作者、题跋、收藏流传、研究者、其他作品和范围未定。只有具有明确本画描绘依据的候选可默认采用到人物档案。
- 论文解释与“可能、推定”等保留证据性质；角色称谓采用下述创作规则。论文转引史料会标明未经独立核对原书。
- **创作称谓规则更新**：已明确在画中的人物，文献只有一种较明确的身份解释时，可直接以该身份命名，例如“鸿胪寺官员”。原画面称谓、身份判断引文及推测性质保留在`creativeNaming`，不因改名变成已核实史实；多个竞争解释、弱猜想或是否在场不明时保留保守称谓。这是全文合并后的判断，不只看某一批。
- 不同作品的同名称谓不自动混合；别名须明确引用关联，依据不足时保留待核对称呼，不合并。原文存在不同说法时保留多份记载，不静默选定一种。
- 自动视觉匹配仅使用范围明确为画中的角色，保留人工对应。文献背景姓名不会自动进入人物档案、剧情或分镜的默认出场名单。
- 内容用途与真实性分开记录：文化信息、人物关系、故事事件、作品信息、流传史、跨作品比较及研究讨论分别归类。三段摘要分别读取对应原文，装裱／收藏过程不默认成为画中剧情，其他作品比较不默认成为本画人物关系。
- 无法逐字定位的引文不会进入依据；仅剔除受影响条目并显示诊断，不改写原文。模型生成但原文找不到的古籍卷次标为待核对；文献本身的卷次和引文仍需人工核查。

## 视觉对应

身份匹配结合编号全图、人物头肩参考、完整裁切和邻近区域。自动提取的外观提示是建议；只有创作者明确勾选的必要条件才是硬约束，明确原文冲突仍会拦截。高把握建议也必须带有效原文引用或已校验提示ID，否则显示候选及拒绝理由，保持未匹配。

已有视觉描述时，可点击「仅重做身份匹配 · 调用 LLM」，避免重复逐人分析。角色称谓的画面对应不代表论文对其官职的推测已被证实；群体角色可以对应多个实例。所有生成结果仍待人工确认。

## 长文、失败与编辑

每批目标4000字符、上限6000字符，约300字符重叠。覆盖全部所选页文；图片／空白页会记录无文字，不假装已经OCR。生成按真实批次显示进度，不显示估算百分比。

已完成批次缓存到本地SQLite；仅相同原文、目标画名、模型输入／提示词和校验版本复用。失败、中断后保留原文及成功批次，重试仍由用户按钮触发。单次模型请求最多一次格式／引用修复，不自动循环重试。

文献整理只生成待采用提案，不覆盖三段输入、人物或人工姓名绑定；用户仍可编辑无关内容。实际输入或结果目标改变时，结果作废而不覆盖编辑。改名不导致任务过期。

## 验收原则

使用本地解析、模拟模型回归和独立项目真实模型验收。生产代码不得包含某幅画的固定人物名单、身份映射或位置。测试案例可以有人工核对的画名和预期，报告应区分解析成功、信息分类正确及实际视觉匹配准确度。
