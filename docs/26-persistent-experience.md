# 体验持久保留与手动刷新

## 使用规则

首次点击“开始体验”会完整准备作品。已有体验只显示“刷新作品”：切回创作再回来、浏览器刷新、重开页面都继续原会话，不自动采用新的制作内容。创作内容变化仅显示轻量提示。

选中人物、画面聚焦、各角色未发送问题、聊天滚动位置及视频播放位置保留。离开体验会暂停视频，返回恢复位置，不强制自动播放。浏览器在本地保存会话标识及上述界面状态；聊天和线索进度仍独立存储在服务端。

手动刷新固定点击时的可用制作内容与素材清单。新内容使用新会话，旧会话和聊天不删除。新作品成功前始终保留原体验；内容和素材均未变化则复用当前会话，不清空输入和进度。不同观众的首次开始不会因作品相同而共享会话；只共享相同的派生图片资源。

## 等待、失败与缓存

等待页依次显示读取作品、准备人物轮廓、载入图片和准备交互。原画、全部画中身影轮廓、头像共用图片、图片解码、透明区域命中数据和首次绘制完成后，才开放操作。视频准备元数据，完整视频按需播放。

失败时显示具体人物或资源原因，提供“重试未完成项”“返回原体验”；没有原体验时可返回创作。不会自动进入只有一部分轮廓的画面。成功的轮廓保留，重试只计算缺失部分。取消保留缓存；离开页面不取消服务端正在进行的准备，回来继续查看已有进度。

资源按原画字节内容、人物位置、分割提示及算法标识缓存。原画复制成带内容校验值的固定素材，避免同一路径被替换后影响旧体验。轮廓有稳定的项目内资源地址，跨会话可共享下载、解码及命中缓存，不重复对同一人物推理。

体验组件按项目保留。返回就绪体验不重新读取整份会话、不提交轮廓准备；就绪体验不轮询创作数据。仅有待完成回答或正在准备时查询必要状态，页面隐藏时暂停查询。聊天和记录线索只更新进度，不重建画面。新视频和新人工选择仅在刷新作品时纳入，记录线索仍可解锁当前清单中的素材。

## 接口与持久化

- `POST /api/projects/{pid}/experience/preparations`：`requestId`、`mode=resume|refresh`、可选 `sessionId`。返回准备 ID、候选会话 ID、状态、阶段、人数与错误；相同请求持久化去重，独立首次开始隔离会话。
- `GET .../preparations/{id}`：读取已有进度；不启动生成。服务重启后的未完成任务显示中断，须明确重试。
- `POST .../preparations/{id}/retry` 和 `cancel`：显式重试缺项或取消；成功缓存不删除。
- `GET .../experience/assets/{key}.png`：按保存的项目资源清单校验权限，返回不可变 PNG，不读取整份制作快照或重新计算全图校验值。原会话轮廓接口保留兼容。
- 会话读取增加公开准备清单；未解锁分镜的正文不放入公开预载清单，公开视频清单只含预载地址。聊天仍仅使用该角色的快照知识。

准备任务与清单存于 `data/experience-preparations/`、`experience-presentations/`；请求回执存于 `experience-preparation-requests/`，资源归属存于 `experience-asset-owners/`。它们引用现有体验会话，无新增 SQL 表，不增加制作版本。会话、聊天和线索进度继续使用原 JSON 持久表。

新准备任务创建的候选会话在轮廓未完成时禁止发送新对话。旧会话按原内容补建清单，保留原对话协议；不会以最新制作资料替换旧知识。启停脚本等待资源准备与已有生成、对话结束后才重载。
