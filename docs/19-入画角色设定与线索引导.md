# 入画角色设定、分段依据与线索引导

## 使用顺序

人物资料与知识确认后，在人物档案的「入画角色设定」点击单人或批量生成。批量只处理尚未填写提示词且前置内容有效的创作角色；已有人设不会被覆盖。选择性格预设、修改完整提示词，核对档案和每条线索的可知时间及引导问题，然后单独确认或用「一键确认本页」。不准备某个角色，不影响其他已准备角色进入体验。

所有生成候选均需核对。性格、说话方式和即时反应没有史料依据时属于创作设定，只能补表达，不新增生平、关系或历史事件。默认身处画中事件当时；年代不明确时不补年份。经历与简介可能包含后来事件，默认待核对，不直接发送给实时模型；姓名始终可用。群体实例共用同一角色ID、人设、聊天与知识。

重新生成保留在建议区；明确「采用角色建议为草稿」才替换编辑内容，仍须确认。采用接口保存当时的依赖版本，运行中改输入或结果区时转为旧输入建议，不自动重试。角色准备可取消，保留原内容；取消无法撤销服务商已经处理的请求。

## 存储结构

继续使用项目workspace的JSON实体，不新增SQL表。草稿、确认内容、修订号、历史依据和乐观锁沿用原规则。

| 实体与字段 | 用途 |
| --- | --- |
| `persona:{characterId}` | 每个创作角色一份独立确认记录，不加入分镜或视频的依赖 |
| `characterId` | 原角色ID；不另建人物 |
| `situation` | 画中当时的历史处境与时间视角 |
| `temperament` | 性格预设或自定义性格，标为创作设定 |
| `speechStyle`、`addressStyle`、`reactions` | 说话方式、称谓与即时反应 |
| `historicalBoundary`、`prompt` | 可编辑边界及完整角色提示词；不能扩大运行时固定边界 |
| `profileTiming` | `identity`、`biography`、`summary`三个档案字段的known／after／uncertain状态 |
| `knowledgeTiming[]` | 原绑定clueId、状态、原因、引导话题topic和建议问题question |
| `generationRefs` | 模型生成依据；手动同步新的知识绑定不改写原生成来源 |
| `experience_config:main` | 独立体验引导配置，位于创作设置，不是剧情或视频依赖 |
| `enabled`、`offTopicThreshold` | 引导开关与1–20轮阈值；未确认配置使用固定默认值true／3，不消费未发布配置草稿 |

角色确认要求人物、资料、知识有效，时间清单恰好覆盖当前确认绑定，至少一条当时可知线索。明确关联「后续」事件的引文不能标当时可知。来源时间不足时生成待核对候选，用户核对后决定；模型猜测不自动获得正式资格。

## 实时对话与发言边框

新会话记录dialogueVersion=2并固定制作、角色、知识和引导配置快照。实时上下文只包含本角色允许的档案字段、当时可知线索、历史依据、未记录线索编号及本角色历史。不传完整剧本、其他角色知识或聊天；未确认内容不进入模型。

模型返回segments段落及disposition（grounded／smalltalk／unknown）。每段含text、basisIds、clueIds；服务端验证编号和对应关系，决定category。answer保留为段落拼接兼容字段。

| 显示 | 服务端判定 |
| --- | --- |
| 实线 · 资料复述 | 逐字匹配允许的已确认supported文本；引用身份仍保持原样 |
| 虚线 · 已有研究推断 | 逐字匹配允许的已确认研究推断，不冒充本人亲历 |
| 无框 · 合理演绎 | 新措辞、第一人称改写、口吻、性格反应及未能直接核对的表达；附引用也不升级 |

段落各自可展开原文、来源版本、定位及转引／观察／研究资料身份。确认不代表已独立核对原书，论文转引不升级为原书验证。纯问候或不知情回答不允许夹带事实编号；涉及资料的回答必须提供允许范围内的依据。仅贴线索编号、不提供属于该线索的依据时拒绝采用。

自然语言演绎的正确性不由编号校验自动证明；本轮模型替身验证协议、范围和状态规则，真实口吻与事实质量需另行授权真实模型验收。固定系统边界优先于人设和观众问题，不允许借自定义prompt扩大历史知识。

## 引导计数与体验操作

整场体验跨角色累计，默认连续3个完成回答未触及未记录线索时给出引导。失败、取消、重复发送和格式修复不重复累计。新线索出现或成功记录线索后清零，重复已收集线索仍视为没有新进展。

候选仅来自本会话快照中可交谈角色及其确认的当时可知、未记录线索。优先当前角色，然后按累计推荐次数、角色ID和线索ID稳定排序。模型回答最多自然引出一个话题，不将仅用于邀请提问的钩子作为已解释线索。

引导显示人物、话题及问题，不直接展示答案，不虚构人物正在做的动作。点击只聚焦人物并填入问题，不调用模型；重复点击保留正在修改的问题，可恢复引导前的未发送问题。观众点击发送才请求回答，点击记录线索才解锁对应分镜或视频。无可用候选或全部已收集时不显示引导。

关闭引导会清零计数，等待下一轮阈值；请求编号和引导编号保证幂等，旧关闭请求不能误关新引导。回答、计数和引导状态在同一事务保存，异常回滚后返回可明确重试的失败状态。

## 接口与兼容

- 原`PUT /api/projects/{pid}/studio/drafts`、单条确认／撤回、批量预览／确认接纳persona及experience_config。
- `POST .../studio/jobs`：task=persona，target为角色ID；留空批量准备未填写角色。复用任务进度、输入摘要、写入范围及并发合并。
- `POST .../studio/jobs/{jid}/cancel`：携带version、kind=persona、id；当前仅取消角色准备，重复取消不会自动重新请求模型。
- `POST .../studio/personas/{cid}/adopt-suggestion`：携带version、kind=persona、id，原子采用建议及其历史依据为草稿。
- 原experience会话／messages／collect接口增加v2角色范围、段落和引导状态。
- `POST .../experience/sessions/{sid}/guidance/dismiss`：携带hintId、requestId，幂等关闭当前引导，不修改制作项目或版本。

旧会话缺少dialogueVersion时视为v1，继续原快照与旧问答策略，不追补人设门槛。旧回答显示「旧版回答，未逐段标注」，不自动伪造三类标签。明确重新开始才进入v2；普通制作修改只提示旧版本。

叙事包3.3包含已确认人设、体验配置、知识时间范围及生成／确认依据版本，不包含聊天、计数、会话标识或密钥。未准备人设不阻止原有制作和分镜导出；离线包不提供模型服务。read_package适配3.0／3.1／3.2旧manifest，旧包保持旧对话协议，不虚构角色或确认；本次不增加导入包到制作项目的入口。

实施前恢复点：上级`merge-backups/persona-guidance-20261101T180710Z/project`，源码和完整data共251个文件，manifest含SHA-256。正式数据不自动确认或生成新角色。上线前另备份完整当前data到同一恢复点的pre-rollout-data，46个文件校验通过，包含实施期间新增的3条旧版对话。

恢复前先保存当前编辑并另备份当前源码与data，停止本项目服务。通常仅还原本次涉及源码并重启；本轮没有SQL结构迁移。若新版已产生体验记录，旧代码不能解释v2新字段，应保留当前数据副本；不要用旧data覆盖后续制作记录。需要完整回到实施前状态时再显式恢复上述project/data。
